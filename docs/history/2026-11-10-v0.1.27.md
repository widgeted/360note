# 2026-11-10 — v0.1.27 对象存储附件与存储用量

## 背景

v0.1.26 已支持整站备份和 S3 备份副本，但附件仍只能落在本机。管理员需要可选的 S3 兼容对象存储来保存附件，并能看到本机与远端占用。

## 实现

- `lib/object-storage.ts`：统一 S3 配置读取、Put/Get/Head/Delete、ListObjectsV2 用量、前缀清理、连接测试；`storage_key` 用 `s3:attachments/...` 标记远端附件。
- `lib/storage.ts`：附件保存/读取/删除/存在性检查按 `storage_key` 路由；保存返回实际生效的 key，调用方必须持久化该 key。
- `services/attachment-storage.ts`：启用/停用迁移、进度状态、大小跳过、同进程迁移锁、用量缓存。
- 新上传、导入、备份恢复都保存 `saveAttachment()` 返回的实际 key；缩略图与原件保持同一侧。
- 整站备份把仅存在于对象存储的附件原样写入归档，确保灾难恢复完整；创建后按设置自动上传。
- 管理端新增对象存储用量、迁移进度、停用清理选项；实例概览显示本机/远端附件与备份占用。
- 有远端附件时禁止修改连接身份字段，避免附件失联。

## 验证

- `tests/manual/object-storage-e2e.mjs`：临时数据库 + 临时数据目录 + s3rver。
- 覆盖本机上传、缩略图、连接测试、启用迁移、直传、停用取回、重复启用跳过、远端删除、整站备份包含远端附件、备份自动上传与远端删除。
- 生产构建、类型检查、现有回归稍后执行。
