# 360note Design System

> 版本 1.0 · 2026-11-08
> 适用范围：Web 应用、公开落地页、登录/注册/找回、公开分享页、系统错误页、导出 HTML/PDF。公开落地页是正式产品入口，未登录访问 `/` 时展示落地页，已登录后直接进入应用。
> 设计参考：Notion 的安静工作区结构、Things 的排版秩序、Memos 的轻量记录感；只借鉴组织方式，不复制外观，不混搭成“缝合怪”。
> 本文是视觉与交互的唯一事实来源。新增组件必须先在这里找到对应规则，或先更新本文。

---

## 1. 设计立场

### 1.1 一句话

**一张午夜色的书桌，铺着温暖的纸。**
界面退到内容之后，绿色只用来表示“可以行动”，其余颜色都属于内容与状态。

### 1.2 三条原则

1. **一屏一个主任务。** 写作时只看到笔记、必要格式工具与保存状态；管理时只看到管理控件。不要同时让编辑和管理争夺注意力。
2. **默认简单，渐进披露。** 新用户只学记录、搜索、同步状态。中频功能出现在选中笔记后的上下文与右侧面板；低频、高焦虑功能进入设置与命令面板。
3. **克制但有性格。** 不用大量卡片、渐变和徽章堆出“功能很多”。用字体、留白、一条绿色和少量深色表面建立识别度。

### 1.3 不是什么

- 不是 Notion 的复制品：没有无限嵌套的数据库视图、没有满屏 emoji 图标、没有营销式渐变。
- 不是 Trilium 的复刻：不把树、属性、脚本全部铺在首屏。
- 不是 Blinko 的卡片墙：卡片只用于选择模板和少量上下文，不作为主界面。
- 不是“缝合怪”：所有页面共享同一套 token、字体、间距、图标与交互。

## 2. 设计 Token

实现在 `apps/web/src/styles/tokens.css`。任何颜色、间距、圆角、字号应优先使用变量，不在组件里发明新值。

### 2.1 品牌色

| Token | Light | Dark | 用途 |
|---|---|---|---|
| `--ink-900` | `#0B1020` | — | 侧栏、深色舞台、主按钮（浅色模式） |
| `--ink-950` | `#070C1C` | — | 深色页面背景 |
| `--paper-100` | `#F8F6F1` | `#0D111E` | 应用底色 / 列表背景 |
| `--paper-50` | `#FDFCF9` | `#0B0E19` | 阅读区、设置背景 |
| `--surface` | `#FFFEFA` | `#0F1322` | 编辑器、卡片 |
| `--surface-raised` | `#FFFFFF` | `#141A2C` | 弹窗、菜单 |
| `--blue`（语义名保留，值为绿色） | `#17865B` | `#5FD3A0` | 唯一主操作色、链接、选中 |
| `--blue-strong` | `#106A46` | `#86E3BA` | 主按钮 hover |
| `--blue-soft` | `#E5F4EC` | `#10291F` | 选中背景、轻提示 |
| `--violet` | `#6C5CE7` | `#A99BFF` | 仅少数装饰/图标，不用于主按钮 |
| `--green` | `#147A5B` | `#4FBD97` | 成功、已同步 |
| `--amber` | `#B96E08` | `#E0A453` | 草稿、警告、自动保存快照 |
| `--red` | `#C23D4E` | `#EF7A88` | 危险操作、错误 |

**规则：**
- 主按钮只允许 `--blue`，禁止在同一个视图出现两个高饱和主色。
- 深色 toast/代码表面使用暖炭色或墨绿色；页面主背景保持暖纸色，绿色只作为小面积行动/链接色。
- 装饰性紫色只出现在图标底、营销页氛围光，不承担状态语义。
- 深色模式不是简单反色：降低饱和度、提高表面层级差，避免纯黑 + 纯白的刺眼对比。
- 颜色不作为唯一信息载体。同步状态永远同时有文字或图标；标签永远有文字；错误有图标与说明。

### 2.2 字体

| 角色 | 字体 | 说明 |
|---|---|---|
| UI、标题、正文 | Inter Variable + 系统中文字体（PingFang SC / Microsoft YaHei / Noto Sans CJK SC / Source Han Sans SC） | 全站唯一正文字体家族；数字使用 `lnum` |
| 代码 | SFMono / JetBrains Mono / Consolas + 中文无衬线回退 | 代码块、ID、令牌、版本号；中文不得落到宋体 |

**明确禁止：**
- **全站禁止任何衬线字体。** 禁止 Songti SC、STSong、SimSun/宋体、Noto Serif CJK、Georgia、Times、Newsreader 等；包括登录页、笔记标题、公开分享页、导出 HTML/PDF 和系统错误页。
- 不引入第二个展示字体家族来“提升设计感”。360note 的识别度来自字重、字距、留白和一条绿色，不来自字体混搭。

**字号尺度（下限 13px）**
- 13px：元数据、快捷键、脚注、法律说明下限
- 13–14px：主要 UI 标签、列表摘要、按钮、表单
- 14–15px：表单输入、正文辅助、菜单项
- 16–17px：编辑正文
- 20–30px：面板/设置大标题
- 30–42px：笔记标题（随视口缩放）
- 44–56px：公开分享页标题（仅公开页）

**规则：**
- **任何界面文字不得小于 13px。** 包括“隐私政策”“服务条款”“忘记密码”、时间戳、快捷键和错误辅助说明。禁止用 10px/11px 的“精致小字”制造廉价感或阅读障碍。
- 编辑器富文本、Markdown 源码、代码块、公开分享页和导出 HTML/PDF 同样遵守无衬线规则；Markdown 源码/代码块的中文回退必须是系统无衬线字体，不能是宋体。
- **同一个功能同一页面只出现一次**：保存状态只在编辑器右上角，字数只在标题元信息，字符数只在编辑器底栏；不得在侧栏/第二个 footer 重复。账户菜单只保留“退出登录”，账户/外观/安全统一从设置导航进入，不在用户菜单重复。
- 大标题使用负字距（-0.03 ~ -0.045em），小字保持 0 或略微正字距。
- 中文字体不合成斜体：`font-synthesis-style: none`。需要强调时用字重、颜色或分行，不用倾斜。
- 不使用全大写中文。英文全大写只用于极小的 section label，且不得小于 13px。
- 一屏最多两个字体家族同时承担结构；代码是第三种，但只出现在代码上下文。

### 2.3 间距与尺寸

- 4px 基准；常用：4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 / 64。
- 侧栏 250px；列表 336px（1080px 下 300px）；信息面板 350px（覆盖式抽屉）；顶栏 52px；工具栏 42px。
- 圆角：5（小控件）/ 8（按钮/输入）/ 11（卡片/下拉）/ 16（弹窗）/ 24（大型容器）。不要在同一层级混用 4 和 20。
- 边框永远细（1px），色值低对比；阴影只用于浮层与选中卡片，不用阴影制造“卡片海洋”。

### 2.4 动效

- 时长 140–320ms，缓动 `cubic-bezier(0.22, 1, 0.36, 1)`。
- 只动 opacity / background / color / transform（仅限弹窗、抽屉、Toast 的进入与退出）。
- **禁止 hover 动效：** 鼠标悬停在文字、链接或按钮上时，不得出现下划线，不得 `translateY` 上浮，不得 `scale` 放大，不得抖动或阴影跳变。hover 只能改变颜色、背景或边框色。
- 禁止 `:active` 让按钮位移/缩小来模拟“按下去”。按压反馈只用背景加深。
- 尊重 `prefers-reduced-motion` 与用户设置 `reduceMotion`。
- 不弹跳、不旋转、不无限脉冲（同步点除外，且极轻）。

## 3. 布局系统

### 3.1 应用三栏

```
┌──────────────┬──────────────────┬──────────────────────────────┐
│ Sidebar      │ Note list        │ Editor / Empty state         │
│ 250px        │ 336px            │ flexible                     │
│ 深色         │ 暖纸色           │ 白色/近白纸                  │
│ 导航/文件夹/ │ 搜索/排序/列表   │ 标题/格式/正文/保存状态      │
│ 标签/状态    │                  │ + Info panel 350px（覆盖）   │
└──────────────┴──────────────────┴──────────────────────────────┘
```

- **Sidebar** 固定品牌与全局导航，不与内容抢注意力；它**跟随主题**：浅色主题是暖纸色侧栏，深色主题才是深色侧栏。不允许主题切换后侧栏保持另一种主题。
- **侧栏导航不能出现“黑块无图标”**：深色底上的图标必须使用显式浅色；不要把侧栏文字 token（会随主题变深）复用为主按钮图标色。
- **头像热区等于头像尺寸**：折叠侧栏的头像按钮不得保留整行或上下 padding 的点击区域；按钮边界应与头像边界一致。
- **List** 是中性暖纸面，负责“发现”和“切换”。选中项用白色表面 + 细边框，而不是高饱和色块。
- **Editor** 是阅读与写作的主舞台，背景最亮（浅色）或最低（深色），标题使用 Inter 粗体，不使用衬线。
- **Context panel** 是选中笔记后的“中频操作区”，默认收起。信息/反向链接/评论/历史四个页签，避免把低频设置塞进每篇笔记。所有宽度下都是右侧覆盖式抽屉（350px，窄屏 86vw），不挤压或遮挡后仍可关闭编辑区。
- **Settings** 进入页面级布局：侧栏保留，列表收起；左侧设置分组，右侧内容最大 720px，避免表单过宽。

### 3.2 响应式断点

| 宽度 | 行为 |
|---|---|
| ≥1241px | 三栏；信息面板为右侧覆盖式抽屉，带轻 scrim |
| 1081–1240px | 同上，列表 336px |
| 901–1080px | 列表缩至 300px；编辑器边距缩小 |
| ≤900px | 侧栏变为抽屉；设置导航单行横向滚动；公开页目录收起 |
| ≤760px | 单屏栈：列表或编辑器二选一；侧栏抽屉；设置 3 列网格；工具栏横向滚动 |
| ≤390px | 标题字号降一档，边距 16px；保证最小字号仍为 13px |

**折叠侧栏：** 折叠后宽度 56px。只显示品牌 mark（完整 `360note.` 文字标识隐藏），通知、展开按钮与品牌纵向分层排列，不要挤在同一行；展开按钮必须切换为 `PanelLeftOpen`，不能继续显示收起图标。底部头像与右侧“…”纵向排列，只有“…”是账户菜单入口，不把整行做成菜单触发器。

移动端不是缩小的桌面：
- 主界面是**列表**；点笔记进入**全屏编辑器**；返回按钮回列表。
- 移动端不设底部快速栏：搜索在列表顶部，收藏、设置和空间切换在侧栏抽屉中；新建笔记只保留顶部搜索框右侧按钮，不在底部重复。
- 设置页从侧栏底部的“设置”进入；移动端导航为 3 列网格（分区较多时自然换行，管理员多“实例管理”），所有设置分区一屏、一触达；返回按钮回到进入设置前的笔记或列表，不丢失当前上下文。
- 编辑时顶部保留返回、面包屑、信息面板和更多；保存状态用点 + 文本（窄屏只留点）。
- 信息面板为右侧抽屉（≤86vw），设置导航为 3 列网格。

### 3.3 一屏一个主任务

- 编辑时：侧栏与列表仍可见（桌面），但编辑器内部不出现“管理卡片”“统计面板”“分享设置”。这些通过右侧面板/更多菜单触发。
- 管理设置时：不显示编辑器；不弹出编辑器工具栏。
- 空状态：只给一个明确动作（新建笔记 / 命令面板），不堆放 6 个引导卡片。
- 分享页：只读文章 + 目录 + 评论；不出现应用侧栏、同步状态、设置入口。

## 4. 组件规范

### 4.1 按钮

按钮只有一套几何：1px 边框、圆角 8px（小号 7px）、字体 13.5px/560、图标 14–16px、图文间距 6–7px。禁止在不同页面出现不同高度、不同圆角或不同边框粗细的“同一种按钮”。

| 变体 | 用途 | 规则 |
|---|---|---|
| `btn-primary` | 当前视图唯一主行动 | 一屏原则上 ≤1 个；蓝底白字、蓝底同色边框 |
| `btn-secondary` | 次要行动/取消 | 白底、1px `--line` 边框、深色文字 |
| `btn-ghost` | 低权重/工具栏 | 透明底、无边框；hover 只变背景 |
| `btn-soft` | 中等权重（分享等） | 浅蓝底、浅蓝边框、蓝字；不承担主行动 |
| `btn-danger` | 确认后的破坏性操作 | 仅确认按钮，不用于入口 |
| `btn-danger-ghost` | 危险入口 | 低权重；hover 只变浅红背景与红字 |

**尺寸只有三档：**
- 标准：高 36px，左右内边距 14px。
- 小号：高 30px，左右内边距 10px，圆角 7px。
- 大号：高 44px，左右内边距 18px（登录提交、向导主行动）。

**硬性规则：**
- 任何按钮的 hover/active 都不改变位置、尺寸或阴影，只改变颜色/背景。
- 同一容器内按钮间距至少 8px；不要用负 margin 让按钮贴在一起。
- 按钮内不加第二个彩色徽章，不叠加渐变、玻璃、内阴影。

### 4.2 输入与表单

**控件尺寸只有四档：**
- 紧凑：30px 高（标签搜索、表格内选择器）。
- 标准：36px 高（设置页、账户、备份、表单）。
- 大号：42px 高（少数字段）。
- 登录提交：44px 高（认证页专用）。

规则：同一页面不得混用 29/34/38/44 等随手写的高度；输入框、下拉框、按钮的边框、圆角、字号必须来自对应档位。

- 输入框标准高 36px（紧凑 30px、大号 42px、认证 44px），1px 边框，圆角 8px；聚焦时绿色边框 + 3px 柔和 ring。
- 标签 13.5px/600，置于输入上方；说明 13px 起，置于下方，低对比但可读。
- 登录/找回表单保持单列；注册页桌面端使用 560px 卡片与 2×2 字段网格（昵称/邮箱、密码/确认密码），移动端回到单列。表单容器必须 `display:flex; flex-direction:column; gap:17px`，不得依赖字段块自然堆叠。
- 除“过期时间 + 密码”这类强关联字段外不随意并排；并排字段必须等宽、顶部对齐。
- 错误就近显示在字段/表单底部，使用红色软底 + 图标 + 14px 正文明示原因与下一步；不使用 `alert`，不把 Nginx/服务器原始 HTML 或状态码直接丢给用户。
- 危险确认使用 Modal，要求明确动词（删除/注销/替换），必要时要求输入 `DELETE`。

### 4.3 菜单与浮层

**统一规则：**
- 普通菜单使用**内容自适应宽度**：`width: max-content`，下限 140px、上限 360px（视口不足时留 12px 边距）；通知中心是固定 320px 的信息面板，不按普通菜单处理。
- 空间切换菜单：展开侧栏时右对齐到触发器右边缘（跟随右侧向下箭头），宽度与触发器一致；收起侧栏时左对齐并使用内容自适应宽度。长空间名称必须换行，不能超出菜单背景。
- 图标“…”触发器使用 `align="end"`，菜单右边缘对齐触发器右边缘。
- 全宽触发器（空间切换、账户）在展开状态下使用 `align="end"`，菜单右边缘对齐触发器右边缘；折叠图标触发器使用 `align="start"`。
- 菜单项统一 31px 高、相同内边距、`white-space: nowrap`、图标在左、动作词在右；不允许同一种菜单出现不同宽度或不同对齐。退出登录等短菜单只需容纳最长选项，不拉满侧栏或视口。
- 浮层 `z-index` 必须高于移动端侧栏（侧栏 60、浮层 70、Modal 80、Toast 100）；移动端空间切换菜单因此不会被侧栏导航遮挡。
- 图标语义必须匹配：安全用盾牌，标签用 `#`，链接用链接图标；不得用标签图标代替安全。
- 空间创建与管理分离：管理进入当前空间设置；创建打开独立创建弹窗，两者不得落到同一个无差别页面。
- 个人空间可以创建多个，只有成员本人可见，可重命名；删除时必须保证账户至少保留一个空间。团队空间可创建多个，支持成员、角色、邀请与审计。


- 使用 portaled popover，点击外部/Esc 关闭；预算宽度 160–240px。
- 菜单项 31px 高，图标 + 文字 + 可选快捷键；危险项置底并用红色。
- 不使用嵌套子菜单。复杂操作（导入、恢复）用向导，不用多层菜单。
- 下拉的 trigger 必须 stopPropagation，避免在文件夹树/卡片上误触父级动作。

### 4.4 弹窗

- 弹窗打开/关闭的焦点管理 effect 只能依赖 `open`，不能依赖每次渲染都会变化的 `onClose`；否则父组件因保存/上传重渲染时会反复抢焦点，导致输入框只能输入一个字，分享窗口闪烁。
- 弹窗内优先聚焦第一个输入/文本域，而不是标题栏关闭按钮。空间命名、分享、上传等弹窗在父组件保存/刷新时必须保持输入焦点。

- 只在“必须打断”的确认、分享、短表单、向导预览中使用。
- 单层为主；避免弹窗里再弹窗。若必须确认，优先在同一弹窗内切换状态（如“再次点击确认”）。
- 标题 16px/650；描述 13.5px/1.6；底部按钮右对齐；移动端从底部升起。
- 关闭按钮 27px；点击遮罩可关闭（危险操作进行中除外）。

- 右侧信息面板在所有尺寸都是覆盖式抽屉（350px / 窄屏 86vw），不挤压编辑区；打开时有 scrim，左侧仍保留笔记可见区域。
- 历史版本使用内联折叠面板（accordion）：展开当前行显示预览和恢复操作，不使用“点击后在列表底部单独预览”的模型。

### 4.4.1 标签展示

- 所有标签使用同一个 `.tag-token` 元素：字面 `#` + 名称，不混用图标库里的 Tag/圆点。
- 标签按内容宽度排列，一行多个；禁止整行/全宽标签。文字过长时省略名称，不撑开布局。
- 侧栏标签可显示笔记数量；右侧信息栏、编辑器底部标签栏不显示数字。
- 标签区与下方设置分隔线之间保留至少 24px 的呼吸距离；标签较多时区域内滚动，不挤压分隔线。
- 编辑器底部固定提供 `# 添加标签`，已有标签以同一 tag-token 显示；超过一行时横向滚动，添加入口始终在最后。
- 添加标签直接在 tag-token 内输入（不弹独立输入框）；Enter 保存并继续下一个空白 token，点击别处时最后一个空白 token 不保存。
- 标签建议必须一行多个、自动换行，不使用每条一行的菜单列表。
- 笔记标题下方不再重复展示标签；标签只在底部标签栏、侧栏和信息抽屉中出现。

### 4.5 笔记列表项

- 标题 2 行；摘要 2 行；日期、标签、星标/置顶。
- Hover 才显示快捷操作（收藏/置顶/恢复/删除），不干扰阅读；快捷操作只淡入，不上移。
- 选中项：白底 + 细边 + 轻阴影；不使用整行蓝底。
- 多选模式：左侧 15px 复选框；顶部选择条显示已选数量与批量动作。
- 空状态：一个图标、一个标题、一句说明、一个动作。

### 4.6 编辑器

- 标题与正文分离：标题是独立字段，Markdown 导出用 frontmatter 保存；正文不重复 H1（服务端/客户端都会剥离与标题完全相同的首个 H1）。
- 格式工具栏只放高频：撤销/重做、标题、粗斜下划删、行内代码、列表、引用、代码块、链接、双向链接、图片、表格、分割线。低频（颜色、对齐、字号）不进主工具栏。
- 斜杠菜单只放块级插入：标题、列表、任务、引用、代码、表格、图片组、分割线、双向链接。
- 图片拖入/粘贴即上传；一次选择多张图片时默认组成 2 列图片组；工具栏可切换 2/3/4 列或拆分为单图。非图片附件插入 Markdown 链接。信息面板只列出仍被正文引用的附件，并提供两次点击确认的删除按钮。
- 图片组用统一的 `<div class="image-grid" data-image-grid="true" data-columns="2|3|4">` 保存，编辑器、分享页、HTML 导出和打印必须使用同一套网格样式；点击组内图片仍打开原图。
- 竖构图图片不得独占整屏：单图屏幕最大高度 60vh，点击可打开原图；网格单元使用固定 4:3 画布和 `object-fit: contain`，移动端 3/4 列自动降为 2 列。打印时图片组允许按行分页，但单个单元格不跨页；单张图片最大高度 150mm，避免一张竖图独占一页和前后出现大片空白。
- 正文最大宽度 812px（可设置 700/980）；默认行高 1.78；段落间距 1.12em。
- Markdown 源码模式**不再显示顶部提示条和 `.source-footer`**：模式切换只由底部 `.editor-footbar` 承担，避免重复控件。源码 textarea 占满可用编辑高度。
- `.editor-footbar` 是唯一底部状态栏：显示模式切换、字数/字符数、版本与聚焦切换；不得再叠加第二个 footer。
- 代码块使用深色表面 + 浅色文字，与主题无关，保证代码可读性。
- 表格使用细边、表头全大写小字，不使用斑马纹；进入表格后显示上下文栏，提供加/删行列与删除整表。
- 链接颜色只使用绿色，不使用下划线；hover 只加深颜色。双向链接在编辑器中只显示笔记标题（`[[`、`]]` 与别名前缀视觉隐藏），普通单击即跳转；找不到标题时通过当前空间搜索解析，不静默失败。

### 4.7 状态与反馈

| 状态 | 表现 |
|---|---|
| 保存中 | 顶栏小点变琥珀色 + “保存中…” |
| 已保存 | 绿点 + “已保存” |
| 离线 | 灰点 + “离线”/“待同步 N” + 页面内轻提示 |
| 保存失败 | 红点 + “保存失败” + 错误横幅（原因、重试、复制正文） |
| 冲突 | 警告横幅 + “已保留副本” + 查看副本 |
| 草稿 | 警告横幅 + 恢复/丢弃 |
| 删除 | 进回收站 + Toast；永久删除需二次确认 |
| 备份/恢复 | 任务进度条 + 结果页；不用阻塞式弹窗 |

Toast 只用于结果，不用于过程；不承载需要用户决策的内容。

### 4.8 公开分享页

- 背景 `--paper-50`，顶栏 64px，品牌 + “安全分享” + 创建 CTA。
- 文章最大 735px；标题 Inter 粗体 34–46px；元数据不小于 13px；目录右侧 210px，无目录时文章居中。
- 评论在正文之后，轻分隔；访客名可选；不显示应用侧栏。
- 密码页：只显示标题、说明、密码输入和品牌；不泄露正文。
- 编辑权限页：直接编辑 Markdown，保存时生成版本；明示匿名可编辑的风险。
- 打印/PDF：隐藏所有 chrome、评论、目录、按钮和分享品牌；只保留标题、作者、正文与附件。打印元信息包含发布与打印的完整时间（`yyyy年MM月dd日 HH:mm`），更新时间为相对时间（如“2 小时前”）；屏幕同样使用相对更新时间。
- 文章页顶栏 CTA 为次级按钮；正文元数据按“作者/发布时间/更新时间 + 右侧操作”分组，移动端可换行；评论表单使用卡片化容器；附件使用带图标的列表；页脚只保留 `360note.` 与安全说明，不重复品牌全称。

### 4.9 空状态

- 应用空状态：Inter 粗体标题“从这里开始。”+ 一句引导 + 新建/命令面板两个动作 + 三条轻提示；图标使用书写类线性图标，不用 AI 闪光、机器人或渐变。
- 列表空状态：图标 + 一句具体原因（无笔记/无匹配/回收站空）+ 一个动作。
- 设置空状态：说明什么会出现在这里，而不是空白。
- 公开页错误：说明可能原因 + 返回/了解 360note。

### 4.11 内联命名

- 新建文件夹/标签属于低维操作，不使用弹窗。点击“+”后在列表最上方出现一行待命名项，输入框边界就是该行名称区域；Enter/失焦保存，Esc 取消。
- 重命名同样在原名位置替换为输入框，不弹窗、不跳页。删除仍使用确认弹窗，因为它是破坏性操作。
- 新建成功后输入框消失，新项保持在同一视觉层级；失败时保留输入内容并提示原因。

### 4.12 通知与深链

- 通知不是“只读提醒”。点击评论通知必须打开对应笔记并定位到评论面板和目标评论；点击“共享笔记被编辑”必须打开版本历史并预览对应版本。
- 通知行显示明确动作词：“查看评论”“查看修改”“查看安全设置”，不能只依赖整行可点击这一隐藏行为。
- 旧通知缺少 panel 参数时，前端按类型补全：评论 → `panel=comments`，共享编辑 → `panel=history&preview=latest`；不能因为历史数据而失效。
- 全部已读后铃铛蓝点必须立即消失；安全通知由真实登录行为产生，测试会话不得留在生产通知里。
- 通知深链使用 `?panel=comments&comment=<id>` 或 `?panel=history&version=<n>`，刷新后仍能恢复同一上下文。

### 4.10 入口与错误页

- 登录页是产品的一部分：品牌 mark + 文字标识、一句说明、邮箱/密码、提交按钮、注册/忘记密码入口、13px 以上的隐私与条款链接。注册页桌面端使用 560px 卡片和 2×2 字段网格，移动端单列；没有虚构的用户评价、价格卡、功能三栏和装饰性大插图。
- 服务不可用（502/503/504）时，Nginx 必须返回 360note 的 503 页面，而不是 Nginx 默认 HTML。页面包含品牌、事实性说明（数据不会丢失）、重试按钮和状态链接。
- 前端请求失败时统一转为用户能理解的中文错误，禁止把 `<html><head><title>502 Bad Gateway...` 渲染到表单或 Toast 中。
- 静态资源由 Nginx 直接提供：即使 API 重启，登录页、错误页和已加载的应用外壳仍然可用。

## 5. 文案与语气

- 中文为主，句子短，少用感叹号。英文使用 sentence case，不 Title Case。
- 不用“超级”“一键搞定”“颠覆”等营销词。
- 状态用事实：`已保存`、`离线`、`已保留副本`，不用“成功！”。
- 危险操作解释后果与可恢复性：“删除后可在回收站中恢复”。
- 隐私与安全文案明确边界：只发送账户与安全邮件、不训练 AI、当前不提供 E2EE。
- 数字与时间使用本地化格式；相对时间用于列表，完整时间用于详情/版本/审计。
- 空状态给行动，不给泛泛的“开始探索吧”。

## 6. 公开落地页

公开落地页是产品入口的主规则，不是附属页面。未登录用户访问 `/` 时看到落地页；已登录用户直接进入 `/app`。落地页与产品使用同一套 token 和绿色主色，不使用第二套视觉语言。

- 顶部：官方标识、功能/安全/关于、语言切换、登录、免费开始。
- 首屏：一句话价值、两个 CTA、一个由真实界面结构组成的无图片产品预览。
- 能力区：六张等高说明卡，不堆叠营销口号。
- 双语区：说明 360biji.com 中文版与 360note.com 英文版共享账户与内容。
- 安全区：明确列出 TLS、scrypt、AES-256-GCM、2FA、设备撤销、邮箱验证码与恢复密钥，并明确说明当前不提供 E2EE。
- 底部：产品、法律、联系方式，以及与“奇虎360”无关的声明。
- 移动端隐藏导航链接与浮层卡片，保留标识、语言切换、主 CTA 与单列内容。

禁止使用轮播、自动播放视频、粒子背景、行为画像脚本或夸大安全承诺。Cloudflare 边缘注入的无 Cookie 汇总访问统计是唯一例外。

## 6.1 管理表格与低频设置

- **管理表格单行优先**：对象、用户、审计、备份等管理表格的列默认不换行；列宽固定/最小宽度，容器横向滚动。不要用多行换行把行高撑大。
- **表格行高固定**：管理表 `td` 统一 6px 垂直内边距和 30px 控件高度，行高约 43px；同一表格所有行等高。
- **筛选与导出**：对象/文件/日志类表格超过 10 行时提供筛选输入；对象/日志提供 CSV 导出。筛选和导出与刷新按钮同一行，桌面不换行，≤760px 才换行。
- **低频/高风险设置折叠**：对象存储 Endpoint、Bucket、密钥、CDN 鉴权、媒体处理等修改频率低且填错会导致附件不可访问的设置，默认只显示状态摘要和“编辑连接设置”；点击后才展开表单。保存成功后自动收起。
- **连接类表单**：Endpoint/Bucket/Prefix/密钥统一使用同一套 `.field`、`.input.mono`、`.btn-sm`；不要为单个页面另造输入框、按钮或状态 badge。
- **媒体域名说明**：媒体访问域名是绑定到附件桶的 CDN/媒体域名根地址，不是 S3 Endpoint，也不是 `<bucket>.<endpoint>` 的字符串拼接；表单必须给出示例和“只填域名根”的限制。域名需完成 ICP 备案；已备案主域的子域名通常无需单独备案，但以 CDN 服务商审核为准。还需在 CDN 控制台绑定附件桶并完成 CNAME 与证书，否则填了也不会生效。
- **同期提示卡片**：Toast、PWA 安装/更新、通知展开行动区必须共用紧凑卡片结构：图标贴标题、正文与标题左侧对齐、关闭在右上、行动在右下或内容下方，不允许一套左对齐一套居中。
- **标题分隔线留白**：`.setting-row` 作为卡片内小标题时使用 `.setting-row-heading`；`border-bottom` 与下一行字段标签或输入框之间至少保留 12–14px。禁止写 `padding-top: 0` 后直接接表单网格。子区块标题使用 `.setting-row-heading-spaced`，与上方按钮保持 20px。

## 7. 图标与插画

- 图标统一使用 Lucide，线宽 1.7–2；尺寸 14–18px，与 13–14px 文字并排时保持视觉平衡。不要混用 Font Awesome、Bootstrap Icons。
- 不在同一视图混用填充图标和线框图标；选中状态可用填充（如星标）。
- 功能图标只在必要时使用；不要每个菜单项都配彩色图标。
- **品牌识别 = 官方 SVG 标识**：英文版使用 `/img/360note.svg`，中文版使用 `/img/360biji.svg`；紧凑场景使用 `/img/360note_icon.svg`。深色背景下通过 CSS 反白，不另画一套图标。业务页面使用绿色作为唯一主操作色。
- **头像**统一为圆形、白色首字母、低饱和深色描边；不得使用亮色圆角方块或与品牌 logo 混淆的图形。
- 公开分享页与法律页沿用同一 mark + 文字标识，不另造一套视觉。

## 8. 可访问性

- 正文对比度 ≥ 4.5:1；小字 ≥ 4.5:1；大标题可 ≥ 3:1。
- 所有可点击元素有可见 focus ring（2px 绿色 + offset）。
- 图标按钮必须有 `aria-label` 和 `title`；装饰图标 `aria-hidden`。
- 模态框：焦点锁定、Esc 关闭、关闭后焦点回触发按钮；移动端不依赖 hover。
- 表格/列表保持语义；可键盘操作；快捷操作不只靠 hover（移动端可用长按/菜单）。
- 播放/语音/麦克风功能必须由用户主动触发，并提供失败说明。
- 动效可关闭；文字可缩放至 200% 不破版（使用相对单位与换行）。
- 颜色不作为唯一状态；错误/成功都有图标与文字。

## 9. 反模式清单

- ❌ 主界面出现三个以上绿色主按钮。
- ❌ 侧栏放备份/恢复/2FA/API 等低频设置。
- ❌ 每个笔记都显示分享、版本、导出、AI 四个常驻按钮。
- ❌ 用弹窗堆叠弹窗；用 alert/confirm 原生对话框。
- ❌ 用渐变/玻璃拟态制造“高级感”；用大量阴影制造层次。
- ❌ 在写作区出现统计仪表盘、推荐、AI 自动弹窗。
- ❌ 用红色表示普通强调；用绿色表示可点击。
- ❌ 用 8 种字号、5 种圆角、4 种图标库。
- ❌ **屏幕界面使用衬线字体/宋体**，包括标题、正文、按钮和数字。打印/PDF 导出允许使用衬线体，不强制回退无衬线。
- ❌ **让单张竖构图图片独占整屏或整页**，导致阅读时看不到上下文、打印时前后出现大片空白。多图应使用图片组，单图在打印中限制最大高度。
- ❌ **任何小于 13px 的界面文字**，尤其是隐私政策、服务条款、忘记密码、时间和错误说明。
- ❌ **hover 下划线、hover 上浮、hover 放大、active 位移**；这类“网页特效”不属于 360note。
- ❌ 相邻元素边框重叠、双边框、用 `box-shadow` 伪造第二层边框、选中态再加一圈 ring。选中态只改变边框色或背景。
- ❌ 用 AI 味的渐变球、玻璃卡片、闪光图标、机器人插画或字母描边 logo 充当品牌。
- ❌ 把服务器原始错误页、堆栈、状态码直接展示给用户。
- ❌ 主题切换后侧栏仍是另一套色；折叠侧栏图标挤压或不切换图标。
- ❌ 为“新建文件夹/标签”这类低维操作弹窗；应内联命名。
- ❌ 通知只告诉用户“发生了什么”，却不给可点击的评论/版本/设置深链。
- ❌ 同一产品出现两套 favicon/PWA 图标或两种设备图标语言。
- ❌ 深色底上复用一个会变深的文字 token 作为图标色，导致按钮看起来像黑点。
- ❌ 浮层内部滚动时自动关闭浮层；滚轮/滚动条是使用浮层的一部分，不是“离开”。
- ❌ 标签用圆点且一行一个；标签必须用 # 图标并允许一行多个。
- ❌ 设置页输入框高度随手写；必须使用 30/36/42/44 的控件档位。
- ❌ 把“功能多”当成“信息架构”：功能必须有频率和位置。
- ❌ 英文界面只翻译一半；若未完成翻译，不要暴露语言切换（当前版本中文优先）。

## 11. 设计验收清单

- [ ] 是否只有一个主行动？
- [ ] 是否所有颜色/间距/圆角来自 token？
- [ ] 深色模式下是否仍可读、层级清楚？
- [ ] 760px / 390px 是否可用，是否出现横向溢出？
- [ ] 键盘能否完成核心任务（新建、搜索、打开、保存、关闭弹窗）？
- [ ] 状态是否有文字 + 图标，不仅靠颜色？
- [ ] 低频率功能是否能在命令面板搜到？
- [ ] 危险操作是否可恢复或二次确认？
- [ ] 空状态是否给出下一步？
- [ ] 是否引入了新的字体/图标库/视觉语言？
- [ ] 屏幕界面是否没有衬线/宋体？打印样式允许衬线，不需要强制回退无衬线。
- [ ] 是否所有文字 ≥ 13px？抽查隐私政策、服务条款、忘记密码、时间戳和错误说明。
- [ ] hover/active 是否只改颜色，没有下划线、位移、缩放？
- [ ] 相邻容器/按钮的边框是否重叠或出现双线？
- [ ] 分隔线/边框是否与相邻文字或输入框保持至少 12px 间距，没有出现“线贴字”？
- [ ] 按钮/输入框是否只使用共享 `.btn`/`.input`/`.select` 尺寸与 token，没有页面级一次性样式？
- [ ] 管理表格是否单行、等高、可横向滚动，并提供筛选/导出（适用时）？
- [ ] 低频/高风险连接设置是否默认折叠，保存后收起？决不能让用户误触 Endpoint/Bucket/密钥。
- [ ] 未登录入口是否展示与产品同一 token/品牌语言的公开落地页，并可直接登录或注册？
- [ ] API 故障时是否显示 360note 503 页面和可读错误，而非 Nginx 原始 HTML？
- [ ] 浅色/深色主题是否同时作用于侧栏、弹窗、输入和错误页？
- [ ] 折叠侧栏是否只显示新 mark，并与通知、展开图标各自有位置，展开图标是否切换？
- [ ] 品牌是否使用官方 `360note.svg` / `360biji.svg`，并且没有第二套图标？
- [ ] 新建/重命名文件夹或标签是否内联完成，而不是弹窗？
- [ ] 评论/共享编辑通知能否一键打开目标评论或目标版本？
- [ ] 信息面板是否在所有宽度都是覆盖式抽屉，且关闭后不留下遮挡？
- [ ] 通知/菜单内部滚轮与滚动条拖动时是否保持打开？
- [ ] 侧栏标签是否用 # 图标、可一行多个，并与设置分隔线保持呼吸距离？
- [ ] 所有设置页输入框是否统一为 36px（紧凑 30px）？
- [ ] 所有卡片 Grid 是否等高，且没有纵向 sibling margin 漏入？
- [ ] 深色背景上的按钮图标是否可见，而不是“黑点”？
- [ ] 普通菜单是否内容自适应（140–360px），图标“…”右对齐？空间菜单展开时是否右对齐并长名称换行？
- [ ] 移动端是否没有底部快速栏，设置是否从抽屉进入并保持 3 列一屏导航？
- [ ] 移动端设置返回是否回到进入前的笔记，而不是无条件回列表？
- [ ] 移动端空间切换菜单是否浮在侧栏之上，可点击切换？
- [ ] 账户菜单是否只有右侧“…”可打开，宽度只够显示“退出登录”？
- [ ] 通知蓝点是否在任何未读为 0 的状态下消失？旧通知是否能打开评论/历史？
- [ ] 折叠头像按钮的热区是否严格等于头像边界？
- [ ] Markdown 源码模式是否没有顶部提示条和第二个 footer？
- [ ] 编辑模式是否按笔记独立记忆，并且设置中的默认格式只影响新笔记？
- [ ] 聚焦模式是否只通过底栏退出，没有悬浮按钮？
- [ ] 打印是否隐藏评论/目录/按钮，并使用完整日期格式？
- [ ] 多图是否可切换 2/3/4 列，竖图在屏幕和打印中不会独占整屏/整页？
- [ ] Banner/Toast 的图标、首行文字和关闭按钮是否按同一网格对齐？
- [ ] “创建空间”和“管理空间”是否进入不同状态，而不是同一个页面？
- [ ] 空间页是否同时展示个人空间和团队空间，并说明两者区别？
- [ ] favicon、PWA icon、apple-touch 是否来自同一图标源？
